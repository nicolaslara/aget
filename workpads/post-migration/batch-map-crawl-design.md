# Batch, Map, And Crawl CLI Backlog Design

## Scope

This is the CLI-first backlog for bounded multi-URL workflows:

- `aget batch`: fetch an explicit finite URL set.
- `aget map`: extract and filter links from one URL or existing artifact.
- `aget crawl`: combine bounded map plus get traversal.

The implementation must stay local and CLI-only. Do not add a server, daemon,
hosted API, MCP layer, background worker, or site-specific bypass behavior.

## Shared Safety Defaults

These commands process only user-authorized content. They inherit `aget get`
session and privacy boundaries:

- Auth state is opt-in through repeated `--session <name>`.
- Session replay scope is enforced per fetched URL.
- Provider sessions remain login bootstrap inputs, not target-fetch sessions.
- `--inline-content auto` should omit inline content for sensitive/session-backed
  outputs and prefer artifact paths.
- No command should infer paywalls, login walls, CAPTCHA, bot checks, or
  site-specific retry advice.

Network and traversal defaults:

- Default max concurrency: `2`.
- Maximum allowed concurrency: `8` unless a later task explicitly raises it.
- Default per-request timeout: reuse global `--timeout` behavior.
- Default crawl/map link traversal: same origin and same path prefix as the
  start URL.
- Default output: write manifests/artifacts under `AGET_HOME/runs`, not a
  caller-owned directory unless `--output-dir` is explicitly provided.
- Default partial failure behavior: continue independent work, record failures,
  and return a deterministic summary.
- Exit code: `0` only when every requested item succeeds; `1` when any item
  fails after producing a valid partial-failure manifest.

## Shared Output Model

Every multi-URL command creates a run directory:

```text
AGET_HOME/runs/run-<pid>-<nanos>/
  manifest.json
  manifest.md
  items/
    000001/
      metadata.json
      content.md
    000002/
      metadata.json
      content.md
```

The manifest is the command-level artifact. Per-URL fetches can reuse the same
metadata/content contract as `aget get`, but they should be nested under the
command run directory when generated by `batch` or `crawl`.

JSON envelope shape:

```json
{
  "ok": false,
  "schema_version": "aget.envelope.v1",
  "command": "batch",
  "data": {
    "summary": {
      "requested": 3,
      "succeeded": 2,
      "failed": 1,
      "skipped": 0
    },
    "artifacts": {
      "manifest": ".../manifest.json",
      "markdown": ".../manifest.md"
    },
    "items": []
  },
  "warnings": [],
  "timing_ms": {
    "total": 1234
  }
}
```

`ok` is false when any item failed, even if the command produced usable partial
artifacts. This mirrors agent expectations: the envelope is valid, but the
operation was only partially successful.

## `aget batch`

Purpose: fetch explicit URLs without discovery.

CLI shape:

```text
aget batch <url> [<url>...]
aget batch --file urls.txt
aget batch --stdin
aget batch --file urls.txt --session docs --content-format markdown --concurrency 2
```

Input rules:

- Require at least one source: positional URL, `--file`, or `--stdin`.
- Reject mixed `--stdin` plus positional URLs unless a future task explicitly
  supports merging sources.
- `--file` is newline-delimited. Ignore blank lines and `#` comment lines.
- Deduplicate exact URL strings by default while preserving first-seen order.
- Only HTTP(S), `raw:`, `raw://`, and `file://` inputs are allowed, matching
  `aget get`.

Options:

```text
--file <path>
--stdin
--session <name>...
--content-format <markdown|html|text|json>
--selector <css>
--exclude-selector <css>
--wait-for-selector <css>
--max-chars <n>
--backend-option <aget.key=value>...
--concurrency <n>
--output-dir <path>
--fail-fast
```

Safety limits:

- Default concurrency `2`, max `8`.
- `--fail-fast` stops scheduling new URLs after the first failure, but already
  running requests may finish and must be recorded.
- Session replay scope is checked independently per URL.
- External `--output-dir` is caller-owned; generated files inside it should not
  be pruned by `aget artifacts` unless they are also inside `AGET_HOME/runs`.

Partial failures:

- Continue by default.
- Each item records `status: ok|failed|skipped`, URL, index, artifact paths, and
  redacted error code/message.
- Duplicate URLs can be reported as `skipped` with `reason: duplicate` if the
  implementation chooses to surface deduplication explicitly.

## `aget map`

Purpose: extract links from one fetched page or an existing artifact. It does
not recursively crawl.

CLI shape:

```text
aget map <url>
aget map --artifact <run-id>
aget map <url> --same-origin --same-path --max-links 200
aget map <url> --include '/docs/**' --exclude '/logout'
```

Inputs:

- Exactly one of `<url>` or `--artifact <run-id>`.
- URL mode fetches/extracts the page first, using `aget get` options where
  relevant.
- Artifact mode reads existing internal run metadata/content from
  `AGET_HOME/runs/<run-id>`. It must reject external caller-owned paths unless
  the user supplies a later explicit read-external flag; do not add that flag in
  MAP-001.

Options:

```text
--session <name>...
--selector <css>
--exclude-selector <css>
--wait-for-selector <css>
--same-origin / --any-origin
--same-path / --any-path
--include <pattern>...
--exclude <pattern>...
--max-links <n>
--content-type <type>...
--output <markdown|json>
```

Defaults:

- `--same-origin` default true.
- `--same-path` default true for path-like URLs, preserving the start directory
  prefix. Example: start `/docs/guide/intro` defaults to `/docs/guide/`.
- `--max-links 500`.
- Deduplicate by normalized absolute URL.
- Drop fragments by default when deduplicating.
- Keep query strings by default because docs/search pages sometimes use them,
  but future flags may strip queries.

Output:

- Markdown mode: bullet list grouped by host/path prefix.
- JSON envelope: `links` array with `url`, `text`, `source_url`,
  `same_origin`, `same_path`, `content_type` when known, and `reason` for
  excluded/skipped links if verbose mode later supports it.

Safety:

- Do not fetch discovered links in `map`.
- Do not inspect robots or site policy in v1; record that policy control remains
  a later explicit task.
- Do not include page content in map output beyond link text and URLs.

## `aget crawl`

Purpose: traverse links and fetch pages using a bounded map plus get pipeline.

CLI shape:

```text
aget crawl <url> --limit 25
aget crawl <url> --limit 50 --same-origin --same-path --concurrency 2
aget crawl <url> --limit 20 --session docs --max-depth 2
```

Required safety controls:

- `--limit <n>` is required.
- Maximum accepted `--limit` for v1: `100`.
- Default `--max-depth 2`.
- Maximum accepted `--max-depth`: `5`.
- Default `--concurrency 2`, max `8`.
- Default `--same-origin` and `--same-path`.
- Require explicit `--any-origin` to leave the origin.
- Require explicit `--any-path` to leave the start path prefix.
- `--allow-domain <domain>` may broaden traversal only to listed domains; it
  does not override session replay scope.

Options:

```text
--limit <n>
--max-depth <n>
--concurrency <n>
--same-origin / --any-origin
--same-path / --any-path
--allow-domain <domain>...
--include <pattern>...
--exclude <pattern>...
--session <name>...
--content-format <markdown|html|text|json>
--selector <css>
--exclude-selector <css>
--wait-for-selector <css>
--max-chars <n>
--output-dir <path>
```

Traversal behavior:

- Use breadth-first traversal for deterministic ordering.
- Seed URL is item `0`.
- Dedupe normalized URLs globally.
- Discover links from successfully fetched pages only.
- Stop when `--limit` fetched-or-scheduled pages is reached.
- Record skipped links with reasons in the crawl manifest summary, but do not
  make every skipped link a full item unless verbose mode is added later.

Sessions:

- A repeated `--session` applies to each fetched URL.
- Existing replay-scope enforcement rejects out-of-scope sessions per URL.
- If one URL fails replay scope, that item fails but the crawl can continue for
  other in-scope URLs unless `--fail-fast` is added later.

Rate controls:

- v1 minimum delay between scheduling requests to the same host: `250ms`.
- Future flag: `--delay-ms <n>`, range `0..=10000`.
- Do not implement adaptive anti-bot behavior or site-specific throttling.

Artifacts:

```text
AGET_HOME/runs/run-.../
  crawl-manifest.json
  crawl-manifest.md
  queue.json
  items/
    000000/
      metadata.json
      content.md
    000001/
      metadata.json
      content.md
```

Partial failures:

- Manifest summary includes `succeeded`, `failed`, `skipped`, `discovered`,
  `scheduled`, and `limit`.
- Item records include parent URL, depth, status, error, artifact paths, and
  discovered link counts.
- Exit code `1` when any scheduled item failed, while still writing manifest
  artifacts.

## Implementation Order

1. `BATCH-001`: implement explicit URL batch fetch first. It proves manifest
   shape, per-item artifacts, concurrency limits, partial-failure semantics, and
   output directory behavior without discovery.
2. `MAP-001`: implement one-page link extraction from URL or internal artifact.
   It proves URL normalization and filtering without recursive fetch.
3. `CRAWL-001`: combine map plus batch semantics with a breadth-first queue and
   required `--limit`.

## Test Plan

`BATCH-001`:

- parser/help tests
- positional URL list, `--file`, and `--stdin`
- rejects no input and invalid concurrency
- per-item artifacts and manifest JSON shape
- partial failure exits non-zero with manifest present
- session replay scope checked per URL

`MAP-001`:

- parser/help tests
- extracts and normalizes links from a mock page
- same-origin and same-path defaults
- include/exclude filters
- `--max-links`
- artifact input rejects external content paths
- markdown and JSON output

`CRAWL-001`:

- parser/help tests
- requires `--limit`
- same-origin/path defaults
- breadth-first deterministic order
- `--max-depth`
- partial failure manifest
- session replay scope failures do not leak secrets
- artifacts are internal and compatible with `aget artifacts`

## Open Questions For Later Tasks

- Whether `batch` should support `--inline-content` at all, or always use
  manifest/artifacts to avoid huge envelopes.
- Whether `map --artifact` should support reading caller-owned external
  `--output` paths with an explicit opt-in flag.
- Whether a future config file should set default concurrency/delay limits.
- Whether robots/policy controls should be implemented before broad public
  crawling; for v1, bounded same-origin/path traversal remains the safety
  mechanism.
